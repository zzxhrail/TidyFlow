# ADR 0003：用「监听收文件目录」接住聊天工具的文件

- 状态：已采纳
- 日期：2026-11-22

## 背景

需求是「自动接住 QQ / 微信 / 钉钉上的文件」。可能路线有四条：

1. **注入客户端进程 / hook 文件传输模块**，拿到传输事件直接落盘。
2. **逆协议、自建登录**，用协议库收发。
3. **读客户端本地数据库 + 监听落盘目录**。
4. **纯监听落盘目录**（客户端本来就会把文件写进固定目录）。

## 决策

走第 4 条，配合第 3 条的「目录探测」：`SourceDirectoryResolver` 探测各客户端默认收文件目录，`IncomingWatcher` 轮询这些目录。

## 理由

- **升级免疫**：QQNT / 微信 4.x 一年多次改内部结构，注入点必炸；收文件目录是产品级约定，几年不变。
- **不越界**：不注入、不读内存、不碰登录态，杀软不会按注入行为拦截，也不会因客户端反注入而崩溃。
- **可观测可调试**：出问题就是「目录里有没有文件」，资源管理器即可验证，不用调试器挂进程。
- **跨版本成本低**：换版本只改候选路径表，一行一条。

## 代价与缓解

| 代价 | 缓解 |
| --- | --- |
| 只能拿到已落盘的文件，拿不到「对方正在传」的进度 | 产品语义本就是「收到后归档」，不需要进度 |
| 用户改过客户端下载目录会漏 | 设置里可手动添加任意监听目录；面板明确显示「未检测到目录」 |
| 轮询有 2 秒级延迟 | 间隔可调；归档在后台，用户无感 |
| 复制大文件时可能读到写一半的内容 | 连续两轮大小一致才上报（`ScanOnce` 两段式探针），且有自检用例守住 |

## 备选为何否决

- **注入 / hook**：客户端有反调试与完整性校验，维护成本高于收益；一旦被判定为注入，用户侧风险不可控。
- **协议逆向**：要维护登录态、风控与封号风险，且只覆盖单一客户端。
- **只读数据库**：拿得到消息记录，拿不到文件本体，仍要回到目录。
