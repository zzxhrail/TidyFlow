# ADR 0005：安装/卸载界面做在同一个 exe 里

- 状态：已采纳
- 日期：2026-11-22

## 背景

需要「有安装界面（可选安装位置、开机自启、快捷方式）」和「卸载界面」。候选：

1. WiX MSI + 自定义 UI 对话框；
2. 独立的 Setup.exe（WPF/.NET），把主程序内嵌成资源；
3. 安装/卸载界面就是主程序自身的两个模式。

## 决策

走第 3 条：同一个可执行文件按入口分三种模式——

| 触发 | 模式 |
| --- | --- |
| 文件名以 `DeskFlow-Setup` 开头，或带 `--install` | 安装界面 |
| 带 `--uninstall` | 卸载界面 |
| 其它 | 正常面板 / 命令行 |

安装包 `DeskFlow-Setup-<版本>.exe` 就是主程序的改名副本（`build/pack-installer.ps1` 复制一份）。

## 理由

- **体积**：独立安装器要在自己的 .NET 运行时之外再塞一份 59 MB 的自包含程序，安装包会变成 120 MB+；改名副本总大小仍是 59 MB，且安装器天然自带运行时，目标机什么都不用装。
- **一致性**：安装位置、快捷方式、注册表、自启只有一份实现（`DeskFlow.Deployment.InstallLayout`），安装器和卸载器不会各写一套然后慢慢跑偏。
- **可测试**：`--install --silent` / `--uninstall --silent` 让自动化能跑完整安装-卸载闭环，不需要 UI 自动化。
- **卸载入口天然存在**：注册表 `UninstallString` 指向安装目录里的主程序 `--uninstall`，不需要额外复制一个 59 MB 的 Uninstall.exe。

## 代价与处理

| 代价 | 处理 |
| --- | --- |
| 下载到的「安装包」与「程序」同名同大小，容易混 | 安装包固定命名 `DeskFlow-Setup-<版本>.exe`，窗口标题写「安装程序」 |
| 卸载时要删除自己所在的目录 | 交给隐藏的 PowerShell 脚本延迟删除：先等进程退出，再重试删除（最多 20 秒） |
| 中文路径在 .cmd 里会被按本地代码页读坏 | 辅助脚本改用 .ps1 + UTF-8 BOM，PowerShell 一定按 Unicode 读 |
| 企业批量部署可能仍要 MSI | `pack-installer.ps1 -Msi` 仍可产出 WiX 打的 per-user MSI |
